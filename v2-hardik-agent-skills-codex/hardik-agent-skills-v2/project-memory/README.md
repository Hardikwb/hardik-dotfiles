# Project Memory

Persistent project context for agents. Read this file first, then open only what the task needs.

- `overview.md` — project purpose and boundaries
- `architecture.md` — broad system structure
- `components/` — component responsibilities
- `flows/` — important control/data flows
- `contracts/` — APIs, events, external contracts
- `database.md` — persistence model overview
- `conventions.md` — stable project conventions
- `testing-map.md` — where relevant tests live
- `decisions.md` — accepted architectural decisions

Rules:

1. Keep entries concise and factual.
2. Prefer paths and references over copied code.
3. Record verification dates and source paths for important claims.
4. Update only memory affected by a change.
5. Persistent updates require user approval unless the project later enables an explicit automatic-memory policy.
