# Questions

Ask questions only when the answer is unavailable from the user, memory, or repository and would materially change the design.

Order:

1. user intent / outcome
2. scope and boundaries
3. behavior and important edge cases
4. constraints / scale / integrations
5. implementation decisions

Use one group at a time. Keep each question concrete.

For hard choices, prefer 2–3 options with short tradeoffs.

Do not ask implementation questions before the product/system behavior is clear.

Do not invent defaults unless the user explicitly tells you to assume.
